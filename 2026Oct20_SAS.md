## EXECUTIVE SUMMARY & PURPOSE

This document is the **definitive, end-to-end technical specification and AI rebuild prompt** for **SetAndSit**. If the codebase must ever be reconstructed from scratch or substantially extended by an autonomous AI agent or engineering team, this document contains every architectural rule, clinical taxonomy definition, data model, audio scheduling formula, lifecycle handling pattern, and design system specification developed to date.

### Core Value Proposition: The "Set and Sit" Paradigm
Unlike conventional meditation apps where users pick an arbitrary duration and listen to a looped static MP3, **SetAndSit is an exact-finish-time clinical scheduling system**:
1. The user specifies a target wall-clock finish time (e.g. *"I must finish at 7:45 AM before my commute"*) or a practice duration (3 to 90 minutes).
2. The dynamic engine selects clinical archetypes, queries asset banks containing 15 randomized variations per segment across two voice personas (Kia and Grace), and dynamically calculates spoken guidance time, inter-segment micro-pauses, and variable integration silence ($S13$).
3. **Exact Closing Sequence:** The session resolves with a closing sequence:
   $$\text{4.0s Pre-Bell Silence} \longrightarrow \text{Closing Bell (e.g., 15s)} \longrightarrow \text{2.0s Pause} \longrightarrow \text{S16 Vocal Outro} \longrightarrow \text{3.0s Closing Stillness}$$
   The practice completes **to the exact second** of the target finish time, with zero truncated audio or abrupt cutoffs.

## 2. THE 16-SEGMENT CLINICAL TAXONOMY ($S01$–$S16$)

SetAndSit replaces generic mindfulness scripts with a 5-phase somatic arc designed to stabilize the nervous system, prevent disorientation, and respect user agency:

| Code | Title | Phase | Clinical Function & Voice Guidance Rules |
| :--- | :--- | :--- | :--- |
| **S01** | External Arrival | Phase 1: Arrival & Agency | Sensory orientation to space, lighting, gravity. Never forces immediate eye closure. |
| **S02** | Permission and Choice | Phase 1: Arrival & Agency | Explicit autonomy; choice of posture (sit, lie, standing), eyes open or soft gaze. |
| **S03** | Breath Orientation | Phase 1: Arrival & Agency | Gentle awareness of natural breathing without forced pacing, counts, or holds. |
| **S04** | Somatic Grounding | Phase 1: Arrival & Agency | Proprioceptive contact points with chair, floor, cushion; physical weight. |
| **S05** | Safety / Resource Priming | Phase 1: Arrival & Agency | Establishing a neutral somatic safe-harbor (hands, feet, neutral zone). |
| **S06** | Attentional Anchor | Phase 2: Attentional Anchoring | Selecting a single anchor (breath sensations, hands, or room soundscape). |
| **S07** | Core Method Loop | Phase 2: Attentional Anchoring | Spacious guidance delivering the core mindfulness mechanism. |
| **S08** | Wandering-and-Return | Phase 2: Attentional Anchoring | Normalizing cognitive wandering; friendly, neutral redirection cues. |
| **S09** | Expansion / Open Awareness| Phase 3: State Cultivation | Panoramic, spacious observation of thoughts and ambient sensations. |
| **S10** | Affective Cultivation | Phase 3: State Cultivation | Benevolent intentions, self-warmth, heart-centered compassion (Metta). |
| **S11** | Cognitive Inquiry | Phase 3: State Cultivation | Inquiry into impermanence, observer perspective, metacognitive inquiry. |
| **S12** | Imagery Sequence | Phase 3: State Cultivation | Somatic visual-spatial relaxation (warmth, grounded elements, NSDR/Nidra). |
| **S13** | Integration Silence | Phase 4: Deep Silence | Unguided deep silence. **Dynamic scheduling buffer** that absorbs time drift. |
| **S14** | Meaning Transfer | Phase 5: Re-Orientation & Close | Bridging the cultivated state into daily living and interpersonal presence. |
| **S15** | External Reorientation | Phase 5: Re-Orientation & Close | Extremity wiggles, gentle movement, sensory opening to light to avoid dizziness. |
| **S16** | Closing Vocal Cue | Phase 5: Re-Orientation & Close | Final gentle verbal conclusion spoken after the closing bell. |

## 4. DYNAMIC SCHEDULING & TIMELINE MATHEMATICS

### The Dynamic S13 Calculation Formula
The total target duration $T_{target}$ in seconds is partitioned into fixed elements, micro-pauses, and variable integration silence ($S13$).

1. **Initial Settling Pause ($P_{settle}$):**
   Fixed at **4.0 seconds** of silence before $S01$ starts. Meditations in SetAndSit **never start with a harsh bell**.

2. **Pre-Closing Guidance Duration ($T_{guidance}$):**
   Sum of spoken MP3 clips for all active guidance segments (excluding $S13$ and $S16$):
   $$T_{guidance} = \sum_{seg \in Pipeline \setminus \{S13, S16\}} D(seg, variant)$$

3. **Inter-Segment Micro-Pauses ($P_{segment}$):**
   Placed between consecutive guidance segments ($N_{transitions} = \text{length}(PreClosingSegments) - 1$):
   $$P_{segment} = \begin{cases} 
   2\text{s} & \text{if } T_{target} \le 300\text{s (3–5 min)} \\
   6\text{s} & \text{if } 300\text{s} < T_{target} \le 900\text{s (5–15 min)} \\
   14\text{s} & \text{if } T_{target} > 900\text{s (>15 min)}
   \end{cases}$$
   $$T_{micro} = N_{transitions} \times P_{segment}$$

4. **Closing Unit ($D_{close}$):**
   Fixed sequence guaranteed to conclude the practice safely:
   $$D_{close} = P_{pre\_bell}\,(4\text{s}) + D_{bell}\,(15\text{s}) + P_{bell\_voice}\,(2\text{s}) + D(S16)\,(4\text{–}7\text{s}) + P_{stillness}\,(3\text{s})$$

5. **Dynamic Integration Silence ($S13$):**
   $S13$ absorbs all fractional clip lengths and remaining time budget:
   $$T_{fixed\_without\_s13} = P_{settle} + T_{guidance} + T_{micro} + D_{close}$$
   $$D(S13) = \max\Big(0, \text{round}\big(T_{target} - T_{fixed\_without\_s13}\big)\Big)$$

### Adaptive Test Pipeline for Short Windows ($< 180\text{s}$)
* **The Clinical Bottleneck:** A full 10-segment pipeline contains 8 voice segments ($\approx 95\text{s}$) + bells & closing unit ($\approx 29\text{s}$) + settling pause ($4\text{s}$) = $\mathbf{\approx 128\text{–}145\text{s}}$ of fixed audio.
* **The Solution:** If $T_{target} < 180\text{s}$ (e.g. 60s, 90s, 120s for testing), the engine automatically activates a condensed clinical test pipeline:
  $$\text{Pipeline}_{\text{test}} = [S01\text{ (Arrival)}, S04\text{ (Grounding)}, S13\text{ (Silence)}, S16\text{ (Outro)}]$$
  Fixed guidance is $\approx 28\text{s}$, allowing test sessions from 60s to 179s to finish with 100% mathematical precision and realistic pacing.
* **Production Practice:** Sessions $\ge 180\text{s}$ (3 to 90 minutes) execute the complete 10- to 11-segment archetype pipeline.

## 6. PLAYBACK ENGINE & COUNTDOWN SYNCHRONIZATION

### Core Architecture in `lib/screens/practice_screen.dart`
The practice screen reconciles two independent timing domains:
1. **The Visual Countdown Clock (`_totalSecondsRemaining`):** Decrements once every second via `Timer.periodic`.
2. **The Audio Queue Execution (`sessionQueue`):** Advances via `_audioPlayer.onPlayerComplete` (for MP3/Ogg audio) and `_silenceTimer` (for silence pauses).

### Critical Rules Learned During Development
1. **Decouple Countdown Zero from Audio Termination:**
   When `_totalSecondsRemaining` decrements to 0, **never call `_finishSession()` or stop `_audioPlayer`**. The countdown display simply remains at `00:00` while the audio queue finishes its natural sequence.
2. **Protect S16 and the Bell from Premature Stop:**
   Inside `_finishSession()`:
   ```dart
   final item = currentItem;
   final isBellPlaying = item is PlayAudioItem && item.isBell;
   final isOutroPlaying = item is PlayAudioItem && item.segment == ClinicalSegment.S16;

   if (!isBellPlaying && !isOutroPlaying) {
     await _audioPlayer.stop();
   }
   ```
   This prevents the final vocal outro or ringing bell from being abruptly silenced mid-sentence.
3. **Sub-second Duration Handling:**
   Audio clips have fractional seconds (e.g. 5.75s). Never round individual segments before summing them; maintain a running `double` accumulator `acc += item.durationSeconds;` and round only when computing timestamps.
4. **Mute/Unmute Resilience:**
   Muting sets audio volume to `0.0`. However, if the closing bell triggers while muted, SetAndSit plays a gentle non-invasive audio chime at `0.35` volume so the practitioner is always aware the session has concluded.

## 8. STEP-BY-STEP REBUILD SPECIFICATION (FOR AI AGENTS)

If rebuilding this application in an empty directory:

### Step 1: Initialize Flutter & Add Assets
1. Execute `flutter create setandsit`.
2. Configure `pubspec.yaml` with `audioplayers`, `shared_preferences`, and `intl`.
3. Populate `assets/raw/session_manifest.json` and `assets/raw/audio_durations.json`.
4. Copy MP3 files into `assets/audio/Kia/` and `assets/audio/Grace/`.
5. Copy acoustic OGG files into `assets/bells/`.

### Step 2: Implement Data Models (`audio_models.dart`)
1. Create `ClinicalSegment` enum with all 16 codes (`S01` to `S16`).
2. Create `ClinicalArchetype` enum with the 4 pipeline definitions.
3. Create `ScriptVariant` and `AudioSegment` classes with JSON deserializers.
4. Implement `SessionItem` sealed class hierarchy (`PlayAudioItem` and `PauseSilenceItem`).

### Step 3: Implement Services
1. `AudioManifestService`: Load `session_manifest.json` and `audio_durations.json` from `rootBundle` in `initialize()`. Implement `getAudioDuration(...)` and `getAudioAssetPath(...)`.
2. `PreferencesService`: Implement JSON state persistence for user duration, selected bell, archetype, and persona using `SharedPreferences`.

### Step 4: Implement `SessionQueueEngine`
1. For silent practice: Generate `PauseSilenceItem` + closing bell `PlayAudioItem`.
2. For guided practice:
   * Select `[S01, S04, S13, S16]` if `targetDurationSeconds < 180`, else `archetype.pipeline`.
   * Pick random variant per segment.
   * Sum pre-closing guidance duration.
   * Calculate closing unit: Pre-bell silence (4s) + Bell + Pause (2s) + S16 Outro + Closing stillness (3s).
   * Calculate inter-segment micro-pauses: 2s ($\le 300\text{s}$), 6s ($\le 900\text{s}$), or 14s.
   * Calculate exact $S13$ remainder: `s13 = max(0, (targetDurationSeconds - fixedWithoutS13).round())`.
   * Assemble items sequentially into `List<SessionItem>`.

### Step 5: Implement UI & Playback Controller
1. Build `ConfigurationScreen` with time calculator `_calculateTargetSeconds()`.
2. Build `PracticeScreen` with `AudioPlayer`:
   * Listen to `onPlayerComplete` to invoke `_advanceQueue()`.
   * Run `Timer.periodic` for countdown display only (never killing audio at 00:00).
   * Run `_silenceTimer` for `PauseSilenceItem` countdowns.
   * Ensure `_finishSession()` protects S16 and the bell.
3. Build `SessionDebugScreen` with exact timeline visualization.
4. Wire up state in `main.dart` with `AppScreen` state router.
